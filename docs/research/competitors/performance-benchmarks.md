# Performance Benchmarks on Apple Silicon: Parallels vs VMware Fusion vs UTM vs CrossOver (x86 emulation costs, Prism, CAD workloads)

_Research date: 2026-09-03_

> Sourcing note. Only GitHub, Microsoft Learn/Support and Autodesk support pages were fetchable; parallels.com, broadcom.com, codeweavers.com, Geekbench Browser and most review sites were blocked by the egress proxy. Facts taken only from search-result extracts are tagged **[via search]** and should be re-verified before external use.

## TL;DR (5 bullets)

- **Same-architecture virtualization is close to native; whole-system x86 emulation is not.** Windows 11 ARM in Parallels on an M4 Mac mini led a Snapdragon X Elite Surface Laptop 7 and a Core Ultra 7 258V in Geekbench 6 single-core but lost multi-core because the VM had fewer cores plus hypervisor overhead [22][23] **[via search]**. By contrast, Parallels' x86 emulator (still a "technology preview" in PD 26) boots Windows in **2-7 minutes**, is capped at **1 vCPU and 8 GB RAM**, and is gated to Pro/Business/Enterprise licences [10][11] **[via search]**; UTM/QEMU TCG booted Windows XP to desktop in ~21 s with bare qemu but ~1 min inside UTM on an M1 Max (2023 issue) [1].
- **The practical route for x64-only CAD is in-guest emulation (Microsoft Prism), not whole-system emulation.** Prism ships in Windows 11 24H2; since the Oct 2025 update it exposes AVX/AVX2/FMA/BMI/F16C to x64 apps [13][14][17]. Overhead is workload-dependent: Microsoft says "most x64 applications are expected to perform comparably" [52] yet also warns of "performance overhead", "reduced battery life and higher latency" [16][18]; a Feb 2026 developer benchmark found AVX2 builds run at about **2/3 the speed of SSE2-4.x builds** under emulation, so vendors should not ship AVX2-only binaries for ARM guests [19] **[via search]**.
- **Graphics, not CPU, is the CAD bottleneck.** Parallels' guest GPU tops out at **DirectX 11.1** plus OpenGL 4.3 (a new Metal-based OpenGL driver in PD 27, Aug 2026, "up to 2.6x" faster OpenGL); DirectX 12 is not implemented [8][9][12] **[via search]**. Fusion offers DX11 for Windows 11 ARM only via VMware Tools (13.5+) [27] **[via search]**; stable UTM 4.7.5 has no accelerated Windows graphics, while the 5.0 beta line adds DX11 (5.0.4) and DX12 via a D3DMetal backend (5.0.5, 2026-09-01) [3][4]. AutoCAD 2025-2027 require **DirectX 12 Feature Level 12_0 for the "Fast" visual styles** and list ARM processors as unsupported (2025, 2026), so a VM user gets the slower legacy pipeline and no vendor support [29][30][31].
- **CrossOver/Wine numbers are game numbers, not CAD numbers.** CrossOver 26 (2026-02-10; Wine 11.0, D3DMetal 3.0, DXMT 0.72, vkd3d 1.18) delivers e.g. ~50 fps Elden Ring at 900p on a base M4 Mac mini and 88 fps Spider-Man Remastered at 1080p medium on an M5 MacBook Pro [37][38][39] **[via search]**, but Autodesk states AutoCAD "is not supported when run using Wine or other Windows compatibility layers" [35]. No published SPECviewperf or AutoCAD timing exists for any of the four products; MIRRORZ will have to generate its own.
- **Resource and battery rules of thumb are vendor-stated, not measured.** Parallels: keep automatic allocation; "half of the total CPUs will provide optimal performance", more than half degrades both host and guest; assign at most half the Mac's RAM [24] **[via search]**. UTM: JIT cache defaults to 1/4 of guest RAM; "Force multicore" is required for multi-core x86-on-ARM emulation "at the cost of correctness" [25] **[via search]**. Battery impact is only anecdotal (an M3 MacBook Pro dropping from 5-8 h to ~1.5 h with a Windows VM running) [26] **[via search]**; nobody has published a controlled test.

## How it works (architecture)

Every option stacks translation layers; the benchmark story is really the story of which layers a workload hits.

1. **Hypervisor layer (Windows 11 ARM guest on M-series).** Parallels' own hypervisor or Apple's Hypervisor.framework; VMware Fusion and UTM use Apple's frameworks. CPU-bound ARM64 code runs near native: Notebookcheck measured an M1 Pro MacBook Pro 14 running Windows 11 in Parallels Desktop 17 at Geekbench 5 **1,545 single / 5,198 multi**, ahead of a Core i7-1165G7 (2021) [21] **[via search]**; a 2026 VMware Fusion review reports Geekbench "nearly 3,000" single / "exceeding 9,500" multi with 10 vCPUs and 6 GB RAM (chip and Geekbench version not stated) [28] **[via search]**; XDA's M4 Mac mini test found the virtualized M4 led in single-core while the Snapdragon X Elite "took a commanding lead" in multi-core "given that the VM was running with fewer cores and the virtualization overhead" [22][23] **[via search]**. Microsoft's authorization page for Parallels notes nested virtualization (WSL2, Sandbox, VBS) is unsupported in this configuration [15].
2. **In-guest x64 emulation (Prism).** x64 apps such as AutoCAD are JIT-translated block-by-block to ARM64; translated blocks are cached per module and shared across apps [13]. Only user-mode code is emulated; "any kernel mode components must be compiled as Arm64" (relevant for dongles, licence drivers, some plotter drivers) [13][16]. Since 24H2 Prism reports AVX/AVX2/BMI/FMA/F16C to 64-bit apps; 32-bit apps must opt in [14]. Prism is tuned for Snapdragon and some optimizations need Snapdragon-only hardware features [13], which is one reason VM-on-Mac numbers should not be extrapolated from Copilot+ PC reviews.
3. **Paravirtual GPU to Metal.** Parallels: DirectX 11.1 and OpenGL (4.3 with the PD 27 Metal driver); no DirectX 12 [8][9][12] **[via search]**. Fusion: DirectX 11 for Windows 11 ARM via VMware Tools since 13.5 (a Broadcom KB still says 3D "not available at this time" for ARM guests - sources conflict; the newer TechDocs statement is preferred) [27] **[via search]**. UTM stable: software rendering for Windows; UTM 5.0 beta: DX11 (5.0.4) and DX12 through a D3DMetal backend (5.0.5) [3][4].
4. **Whole-system x86 emulation (the "run the x64 Windows ISO" path).** QEMU TCG (UTM) or Parallels' x86 emulator translate every guest instruction including the kernel. Parallels: 2-7 minute boot, 1 vCPU, 8 GB cap, no USB, x86_64 Windows 11 24H2 unsupported for lack of SSE4.2 [10][11] **[via search]**. UTM issue #5468 (2023-07-16) measured Windows XP boot-to-desktop: M1 Max, bare `qemu-system-x86_64` TCG ~21 s vs UTM ~1 min; Intel i9, bare qemu TCG ~39 s vs UTM ~6.5 min [1]. UTM docs: JIT cache defaults to 1/4 of guest RAM; multi-core x86-on-ARM needs "Force multicore" at the cost of correctness; enabling TSO on macOS 15 "can greatly improve performance of Intel emulation" [25] **[via search]**.
5. **Wine path (CrossOver, Sikarugir, Gcenx builds).** Rosetta 2 runs an x86_64 Wine (Gcenx builds are `--build=x86_64-apple-darwin` with MoltenVK) [45][46]; Wine maps Win32 to macOS; D3DMetal (Apple GPTK, D3D12/11), DXMT (D3D10/11 to Metal, LGPL-2.1) or DXVK/MoltenVK map DirectX to Metal [43][44][47]. No Windows licence and no hypervisor, but no Autodesk support [35].

## CAD / AutoCAD relevance

- **Autodesk's requirements move the goalposts every year.** AutoCAD 2025: basic 2.5-2.9 GHz "with 8 logical cores", 8 GB basic / 32 GB recommended, "ARM Processors are not supported", DirectX 12 FL 12_0 required for Shaded (Fast)/Wireframe (Fast) [29]. AutoCAD 2026: search extracts of the official article again say ARM processors are not supported [30] **[via search]**; a Microsoft Q&A community answer claiming native ARM64 support in AutoCAD 2026 conflicts with this and is given lower weight. AutoCAD 2027: Windows 11 only, 8 logical cores, **16 GB basic / 32 GB recommended**, DX12 FL 12_0 "required for 'Fast' visual styles", .NET 10; the 2027 article no longer contains the "ARM Processors are not supported" sentence, which is an observation, not a statement of support [31]. Parallels Standard's vCPU/RAM caps (see the sibling Parallels report) and the "half the Mac" rule mean a 16-core/32 GB Mac is the realistic floor for a compliant VM.
- **Autodesk does not support AutoCAD in any of these environments.** "AutoCAD is not a supported product under Virtualization" [34]; AutoCAD Toolsets are Windows-only and "AutoCAD family products are not supported" in virtualized Windows [33]; installation on Windows-on-ARM devices is documented as unsupported [32]; Wine is unsupported [35]. Support-facing KBs nevertheless show Autodesk engineers troubleshooting Parallels: symptoms listed are "overall performance is slow", "linework displays choppy or dashed", sluggish cursor, and a "hardware acceleration is turned off" error, with the fix being to disable AutoCAD hardware acceleration, change SmartMouse to "Optimized for Games", or change resolution [36]; another KB fixes multi-second selection lag by switching the VM from the Apple hypervisor to the Parallels hypervisor [50]; a third says the installer needs Rosetta 2 on the host and the ARM64 VC++ redistributable in the guest [51].
- **What this means for benchmarks.** On an ARM VM, AutoCAD runs x64 code under Prism (CPU penalty), on a DX11.1 paravirtual GPU (no Fast visual styles, so the older display pipeline), often with hardware acceleration disabled per Autodesk's own KB (software rendering). The relevant metrics are therefore regen/zoom/pan frame time on large DWGs, hatch and 3D orbit responsiveness, and startup time, not Geekbench. None of the four products has published such numbers.

## Strengths (what to match)

- **Parallels:** Microsoft-authorized (PD 18-20 on M1-M3), automatic resource sizing, DX11.1 plus a Metal OpenGL 4.3 driver, sub-5 s boot claims, Autodesk KBs that acknowledge it [8][12][15][36] **[partly via search]**.
- **VMware Fusion:** zero price, DX11 for Windows 11 ARM, still shipping twice a year in 2026 [27][40] **[via search]**.
- **UTM:** free, open, QEMU 10-based, Apple Virtualization backend, and a 5.0 beta that already wires D3DMetal into a VM for DX12 - a proof that the Apple GPTK shader path can live inside a hypervisor's display stack [2][3][4].
- **CrossOver:** no Windows licence, no hypervisor overhead, D3DMetal 3.0/DXMT 0.72 graphics that reach 50-88 fps in AAA titles on M4/M5 [37][38][39] **[via search]**.
- **Prism:** transparent per-module translation caches, AVX2 support, per-app compatibility toggles that MIRRORZ could expose for CAD add-ins [13][14].

## Weaknesses (what MIRRORZ must beat)

1. **No DirectX 12 in any shipping VM**, so AutoCAD 2025+ "Fast" visual styles are unavailable; UTM's DX12 exists only in beta [4][8][30].
2. **Whole-system x86 emulation is minutes-to-boot and single-core** (Parallels) or requires correctness trade-offs (UTM Force multicore) [1][10][11][25].
3. **Prism is tuned for Snapdragon**, and some fast paths need Snapdragon-only hardware, so x64 CAD in a Mac VM is slower than the Copilot+ PC reviews suggest [13].
4. **Kernel-mode components are never emulated** - dongle, licence and some plotter drivers must be ARM64 [13][16].
5. **Autodesk support is absent** in all four paths, and its KBs steer users toward disabling hardware acceleration, which makes the "solution" slower [33][34][35][36].
6. **Battery cost is unquantified but large** (forum reports of 3-4x faster drain; Microsoft says emulated apps use more battery) [16][18][26].
7. **Benchmark opacity:** vendor claims come with no methodology; VM 3DMark results are unstable [20][22].

## Reusable code, ideas, and license implications for MIRRORZ

- **UTM (Apache-2.0 front end; QEMU/GStreamer GPL/LGPL statically linked).** The app code is reusable under Apache-2.0, but shipping its QEMU-derived backend pulls MIRRORZ into GPL obligations; UTM's own README flags the mixed licensing [2]. The 5.0 beta's D3DMetal-in-VM design is the most relevant idea (DX12 inside a guest) [4].
- **DXMT (LGPL-2.1, D3D10/11 to Metal).** Dynamically linkable in a commercial product if LGPL terms are honored; it is what Sikarugir and CrossOver ship for DX11, and AutoCAD's non-Fast pipeline is DX11 [43][44][47]. Wine itself is LGPL; Gcenx's macOS builds show the x86_64 + MoltenVK configuration [45][46].
- **D3DMetal (Apple GPTK).** Not on GitHub; licence terms are Apple's and were treated by Whisky's successors as non-redistributable for commercial use - verify before depending on it [5][47].
- **Prism per-app emulation settings** (disable app cache, strict self-modifying code, x87 precision, hide AVX2) are a good template for a MIRRORZ "compatibility profile" UI for CAD plug-ins [14].
- **Benchmark methodology to adopt:** vCPU and RAM = half the Mac, Geekbench 6 plus a DWG regen/zoom/pan script and startup time, three runs each (VM 3DMark variance shows why), and the Windows build stated because Prism changed in Oct 2025 [14][17][22][24].
